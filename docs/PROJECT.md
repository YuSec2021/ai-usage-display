# 项目文档

## 1. 项目概述

### 1.1 名称

暂定名称：**AI Usage**。

### 1.2 问题

Codex 与 Claude Code 的用量分别散落在不同终端会话、应用页面和命令中。用户需要频繁切换工具，才能判断是否接近短周期或周额度上限，也难以快速比较两者的本地 token 消耗。

### 1.3 解决方案

创建一个常驻 macOS 菜单栏的本地应用，将两种工具的额度窗口、重置时间和 token 汇总到同一个弹窗中。

## 2. 用户与场景

### 2.1 目标用户

- 同时使用 Codex 和 Claude Code 的个人开发者。
- 需要在多个项目和终端会话间控制 AI 编程额度的重度用户。
- 希望查看本机使用趋势，但不希望上传会话数据的隐私敏感用户。

### 2.2 核心场景

1. 开始大型任务前，快速判断哪个工具剩余额度更多。
2. 接近额度上限时，查看准确的重置时间。
3. 一天结束时，查看两种工具分别消耗了多少 token。
4. 数据停止更新时，快速知道是 CLI 未安装、尚无活跃会话还是集成失效。

## 3. 产品范围

### 3.1 MVP 包含

- macOS 菜单栏常驻入口。
- Codex 和 Claude Code 两张提供商卡片。
- 短周期与长周期用量百分比。
- 每个额度窗口的本地化重置时间和倒计时。
- 今日 token 汇总；有可靠数据时进一步显示输入、缓存和输出分类。
- 手动刷新与后台自动刷新。
- 浅色、深色、跟随系统三种主题模式；默认跟随系统。
- CLI 检测、数据新鲜度和错误状态。
- 开机启动设置。
- 完全本地的数据处理与缓存。

### 3.2 MVP 不包含

- 代替用户登录 OpenAI 或 Anthropic。
- 抓取网页、Cookie 或未公开的网络接口。
- 修改、购买或重置订阅额度。
- 团队成员排行和组织级账单。
- iOS、Windows 或 Linux 客户端。
- 将会话正文同步到云端。

### 3.3 后续候选功能

- 7 天/30 天使用趋势图。
- 额度达到阈值时发送本地通知。
- 菜单栏文字显示模式与颜色自定义。
- API Key 计费模式的独立统计。
- 导出匿名化 CSV。

## 4. 功能需求

| 编号 | 需求 | 优先级 | MVP 验收 |
| --- | --- | --- | --- |
| FR-01 | 菜单栏显示应用入口 | P0 | 登录后可选自动启动，点击打开弹窗 |
| FR-02 | 显示 Codex 短/长额度 | P0 | 展示百分比、窗口时长和重置时间 |
| FR-03 | 显示 Claude Code 5 小时/7 天额度 | P0 | 首次有效响应后自动更新 |
| FR-04 | 显示今日 token | P0 | 按本地时区聚合且不重复累计 |
| FR-05 | 手动与自动刷新 | P0 | 文件变化后 2 秒内刷新，另有定时兜底 |
| FR-06 | 安装 Claude 集成 | P0 | 不破坏用户现有 status line 配置 |
| FR-07 | 展示连接状态 | P0 | 正常、等待数据、未安装、权限不足、格式不支持 |
| FR-08 | 历史趋势 | P1 | 至少支持最近 7 天 |
| FR-09 | 用量阈值通知 | P1 | 用户可关闭并设置阈值 |
| FR-10 | 数据导出 | P2 | 导出内容不含会话正文 |
| FR-11 | 三态主题切换 | P0 | 浅色、深色和跟随系统即时生效，重启后保留 |

## 5. 非功能需求

- 空闲状态 CPU 平均占用应接近 0%，不得持续轮询全部历史文件。
- 常驻内存目标低于 80 MB。
- 首次扫描可取消，后续仅增量读取。
- 文件解析失败不能导致应用退出。
- 所有日期使用绝对时间存储，按用户本地时区显示。
- 支持浅色、深色、高对比度和 VoiceOver。
- 跟随系统模式应在 macOS 外观变化后自动更新，无需重启应用。
- 核心功能断网可用。

## 6. 信息架构

### 6.1 菜单栏弹窗

- 顶部：产品名、最近更新时间、整体状态。
- Codex 卡片：连接状态、短周期、长周期、今日 token。
- Claude Code 卡片：连接状态、5 小时、7 天、今日 token。
- 底部：刷新、历史、设置。

### 6.2 设置页

- 通用：开机启动、刷新间隔、菜单栏显示模式。
- 外观：跟随系统（默认）、浅色、深色；选择后立即预览。
- Codex：检测结果、数据目录、重新扫描。
- Claude Code：检测结果、安装/修复收集器、恢复原配置。
- 隐私：本地保存内容说明、清除聚合数据。
- 关于：版本、更新、诊断信息导出。

## 7. 状态与提示

| 状态 | 呈现方式 | 用户操作 |
| --- | --- | --- |
| 正常 | 绿色状态点与更新时间 | 无 |
| 尚无数据 | 灰色进度条，“运行一次 CLI 后显示” | 打开对应 CLI |
| CLI 未安装 | 黄色提示 | 查看安装说明 |
| 集成未启用 | 黄色提示 | 安装 Claude 收集器 |
| 权限不足 | 黄色提示 | 重新授权目录 |
| 数据过期 | 橙色状态点 | 手动刷新/查看诊断 |
| 格式不兼容 | 红色状态点 | 更新应用或导出诊断 |

## 8. 隐私与安全

- 默认不启用网络上传。
- 不读取或复制 OAuth token、API key、浏览器 Cookie。
- 解析 JSONL 时只把允许字段映射到内存模型。
- 持久化数据只包含时间、模型、token 数、费用估算和额度百分比。
- 诊断包默认删除用户名、项目路径和会话 ID。
- Claude 集成安装前必须显示将修改的配置，并保留可恢复备份。

## 9. 成功指标

- 95% 的正常刷新在数据变化后 2 秒内完成。
- 解析一条新增事件的 P95 时间低于 50 ms。
- 连续运行 24 小时无明显内存增长。
- 用户无需手工输入账户凭证即可完成首次设置。
- 任何解析失败都能在界面中解释，而不是静默显示错误数值。

## 10. 路线图

### M0：设计基线

- 产品、开发和架构文档。
- 菜单栏视觉原型。
- 固定匿名测试样本格式。

### M1：Codex MVP

- SwiftUI 菜单栏骨架。
- Codex 日志发现、增量解析和额度显示。
- 基础测试与错误状态。
- 三态主题设置和浅色/深色组件样式。

### M2：Claude Code MVP

- status line 收集器。
- 安装、兼容已有配置和卸载恢复流程。
- 5 小时、7 天、上下文和费用显示。

### M3：Beta

- 历史聚合、设置页、开机启动。
- 性能、无障碍和深色模式检查。
- Developer ID 签名与 Apple 公证。

### M4：正式版本

- 自动更新、崩溃恢复和匿名诊断。
- 网站、隐私政策和发布说明。

## 11. MVP 完成定义

- 在一台同时安装 Codex 和 Claude Code 的 Mac 上连续运行 24 小时。
- 两个提供商的额度与重置时间能随新会话更新。
- 重启应用不会造成 token 重复累计。
- 已有 Claude status line 用户仍能看到原来的输出。
- 三种主题均能即时切换；“跟随系统”能响应系统外观变化。
- 删除集成时能够恢复原始 Claude 配置。
- 测试不依赖开发者真实的 `~/.codex` 或 `~/.claude` 文件。
